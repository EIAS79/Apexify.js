# Apexify.js 6.0.0 release candidate

## Release state

Apexify.js is staged as **6.0.0** because the reengineering changes the supported Node runtime line and tightens several runtime/package contracts. This document is release-candidate material only. **It does not publish the package.** Publication to npm remains an explicit separate user action.

Release-candidate branch: `phase14/final-audit-release-candidate`.

Phase 13 package control point: `d19ccd31ec9f9ccabc4ebd5eaa51ff038f0343a5`.

Phase 0 benchmark control point: `5bb74cb3ab385cd161d98c783aa2fa08ee89acd1`.

## Semantic version and supported runtimes

- package version: `6.0.0`
- Node.js: `22.x || 24.x || 26.x`
- repository package manager: `npm@11.19.1`
- FFmpeg/ffprobe: required only by video/FFmpeg-backed operations
- module systems: native ESM and CommonJS
- supported package subpaths: package root, `apexify.js/types`, and `apexify.js/package.json`

The Node support change alone makes this a major release. The staged 6.0.0 package must not be represented as a 5.4.x patch.

## Breaking migration notes

1. **Node 16/18/20 are no longer supported.** Upgrade deployments to Node 22, 24, or 26.
2. **Use package exports only.** Do not deep-import `dist/*`, `lib-next/*`, or other internal paths.
3. **The package-root runtime façade is `ApexPainter`.** Type-only public declarations are also available from `apexify.js/types`.
4. **Prefer `toOutput()` over `outPut()`.** `outPut()` remains a deprecated compatibility alias for the 6.0 compatibility window.
5. **Remote media is subject to centralized network policy.** Private/reserved network targets are blocked by default; trusted-network access is an explicit opt-in.
6. **Rendering/media operations are resource-limited.** Canvas dimensions/pixels, decoded images, remote bytes, GIF work, audio work, video work, batch concurrency, cache state, plugins/assets/fonts, and temporary workspaces are governed by runtime limits.
7. **Errors are structured.** Runtime failures use the `ApexifyError` hierarchy instead of generic `Error` for public/runtime failure contracts.
8. **Plugins must be awaited.** `await painter.use(plugin)` performs serialized transactional installation; registration mutations are rolled back on installation failure, while arbitrary external side effects remain the plugin author's responsibility.
9. **Video operations require FFmpeg/ffprobe.** Custom binaries may be configured explicitly; process execution is argv-based and non-shell.
10. **npm `latest` remains 5.4.5 until publication.** The repository can stage and verify 6.0.0 without publishing it.

## Release highlights

### Runtime and security architecture

- centralized runtime configuration and resource budgets;
- SSRF-aware remote transport with redirect/DNS/IP validation, byte limits, timeout/abort handling, and bounded concurrency;
- bounded TTL/LRU decoded-media cache plus bounded in-flight decode state;
- structured errors and redacted URL/process diagnostics;
- isolated temporary workspaces and argument-vector FFmpeg/ffprobe process execution;
- bounded process output, process duration, and media allocation estimates;
- final Phase 14 hardening for persistent asset/plugin/font registries and template-layout fan-out.

### Rendering and composition

- validated canvas/image/text/chart pipelines;
- scenes, templates, named assets, built-in scene-layer components, and plugins;
- flex/grid template layout with bounded measurement concurrency;
- raster pipeline corrections and golden regressions;
- chart/comparison/combo rendering with package/API verification.

### GIF, video, and audio

- incremental generated-GIF consumption with backpressure;
- bounded ordered static-GIF prefetch;
- centralized media resolution for GIF/video inputs;
- decomposed FFmpeg video operations/pipeline/workspaces;
- procedural WAV/SFX synthesis, presets, sequencing, composition, and video-audio integration;
- deterministic FFmpeg integration tests on Linux CI.

### Package and release engineering

- native ESM and CommonJS builds;
- ESM and CommonJS declaration trees;
- clean-install tarball consumers for runtime and types;
- committed lockfile and pinned npm toolchain;
- `prepack` rebuild gate and `prepublishOnly` full release verification;
- MIT `LICENSE` included in the tarball;
- multi-Node Linux full CI plus macOS/Windows package-runtime smoke.

## Phase 0 to release-candidate benchmark evidence

The final benchmark replays the Phase 0 named workloads. Phase 0 used Node 20 and an older GitHub-hosted runner while the final evidence below used Node 24 and the current runner. Percent changes are therefore **directional**, not a hardware-normalized scientific A/B.

| Workload | Phase 0 | RC | Wall change | Phase 0 peak RSS | RC peak RSS |
|---|---:|---:|---:|---:|---:|
| cold CJS import | 361.807 ms | 207.465 ms | -42.66% | n/a | n/a |
| canvas 1200×630 | 26.981 ms | 28.756 ms | +6.58% | 126,730,240 B | 127,148,032 B |
| text render | 34.065 ms | 41.021 ms | +20.42% | 131,076,096 B | 131,301,376 B |
| single image composition | 34.305 ms | 36.422 ms | +6.17% | 135,966,720 B | 134,971,392 B |
| medium scene | 34.157 ms | 33.634 ms | -1.53% | 138,981,376 B | 137,891,840 B |
| chart render | 18.402 ms | 20.315 ms | +10.40% | 138,981,376 B | 137,891,840 B |
| GIF 30 frame | 546.915 ms | 368.074 ms | -32.70% | 161,935,360 B | 151,232,512 B |
| audio 10 second | 109.795 ms | 105.535 ms | -3.88% | 163,508,224 B | 162,439,168 B |
| video from frames | skipped | 334.813 ms | not comparable | skipped | 163,880,960 B |

The observable wall-time regressions are canvas, text, single-image composition, and chart. They are not treated as hidden wins. The benchmark itself records that the runtime/runner differs from Phase 0, and text/chart output bytes also differ from the historical baseline. Peak RSS is nearly flat or lower across every directly comparable workload: +0.33% canvas, +0.17% text, and lower for the other measured workloads. GIF is the strongest controlled directional improvement at -32.70% wall time and -6.61% peak RSS.

The audio RSS *delta* increased because the final measurement began from a lower process RSS and allocated later-lived audio buffers; its absolute peak RSS still decreased by 0.65%, which is the more relevant ceiling signal for this cross-run comparison.
